# NISTER Commerce Database

This package owns the PostgreSQL Release 1 contract. IDs are generated by the
application as UUIDv7 values; the database deliberately does not substitute
random UUIDv4 defaults. Money is represented as PostgreSQL `bigint` and
TypeScript `bigint`. Quantities cross the driver boundary as fixed-precision
`numeric(18,6)` strings.

## Ledger enforcement

PostgreSQL cannot express a cross-row balanced-journal invariant as a normal
`CHECK` constraint. The migration therefore uses an explicit two-part design:

1. Entry mutation takes a row lock on the journal and is rejected once the
   journal is posted. Posted journals and entries cannot be updated or deleted.
2. `DEFERRABLE INITIALLY DEFERRED` constraint triggers validate at transaction
   commit that every posted journal has at least two entries, all currencies
   and account currencies match, debits equal credits, and a reversal is the
   complete inverse of its original journal.

The application must create the journal and entries in one database
transaction, then move the journal from `PENDING` to `POSTED` in that same
transaction. Corrections use a new, fully reversing journal linked through
`reversal_of_transaction_id`.

## Commands

```bash
pnpm db:generate
pnpm db:migrate
pnpm db:seed
pnpm test
```

`DATABASE_URL` is required for migration and seed commands. The seed is
deterministic and idempotent; it installs system RBAC definitions and the GHS
platform chart of accounts without creating example users, vendors, or orders.
