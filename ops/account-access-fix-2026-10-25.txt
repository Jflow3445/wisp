Confirmed causes
  The admin list stripped non-digits from named usernames. Purge either rejected
  a name as an empty phone number or targeted its numeric suffix, leaving the
  actual RADIUS policy row. The first phone-account fix also rejected legacy
  numeric IDs; the administrator's examples exposed that gap and it was fixed.
  Phone normalization is now limited to recognized phone formats. Names and
  other numeric IDs retain exact identities in listing, deduplication, RADIUS
  aliases, purge and router session removal. No suffix/wildcard deletion is used.

  Separately, purge omitted location profiles, promotion grants and several
  legacy account tables. Admin lookup called a wallet accessor that inserted
  missing accounts, recreating a purged wallet. Existing portal sessions were
  not invalidated, allowing stale access and profile recreation.

  Password change/reset did not revoke existing network sessions. The cookie
  helper was invoked through sudo with the wrong target identity, although an
  existing sudo rule already permits the restricted nister-router account.

Implemented behavior
  Purge verifies removal of the selected account's active authentication,
  policy, wallet, purchase, OTP, profile, referral and legacy records. Production
  portal/RADIUS connections point to the same store, so this uses one transaction.
  Admin lookup is read-only for absent accounts and reports User not found.
  Confirmation, admin authentication, CSRF and location scope checks remain.

  Public password change/reset, admin password change and admin login reset
  commit a durable per-account revision and router sign-out request with the
  credential change. Old password/hash attributes are removed from both phone
  aliases. Existing portal sessions fail their next authorization check. Login
  rechecks credentials under the same account lock to avoid restoring a password
  superseded by a concurrent reset or purge. Normal login does not revoke other
  devices or change the account revision.

  The existing router helper now supports clearing that account's HotSpot
  cookies before removing all its active sessions. It reports success only after
  checking that no matching cookies or sessions remain. Named accounts and
  numeric legacy IDs are matched exactly using validated script-safe names.
  The existing router key, key path and SSH options were preserved. No SSH or
  sudo configuration was modified.

  New nister-account-revocations.timer runs the restricted worker every 30 seconds.
  Tunnel outages retain pending requests and the UI reports pending sign-out.
  Authentication failures remain pending and stop automatic retries for that
  account. Password changes remain committed even if the router is unreachable.
  Deployment creates account_access_revocations with a 64-character account key.
  Keep these revision receipts across future deployments: deleting them could
  permit old portal sessions to match a reused account's initial revision.
  Receipts are security state, not active users, and are excluded from user lists.
