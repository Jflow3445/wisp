Nister presentation simplification - 2026-11-03

Scope
  First-party captive and public pages, customer/account/recovery screens,
  WISP administration and game surfaces, Flight public/member/admin routes,
  marketplace storefront/vendor/admin and mobile role headings.

Standing direction
  DESIGN.md records the user-requested simplicity contract. Root and application
  AGENTS.md files point future development at it. Titles and controls name tasks;
  decorative introductions, repeated subtitles and auth marketing panels are
  removed. Prices, fees, limits, eligibility, verification, consent, errors and
  recovery remain visible where they affect decisions.

Implementation
  Reuse each application's shared layouts and headers. No new runtime dependency
  or cross-product framework. The public Wi-Fi site uses a small stylesheet and
  direct coverage/access actions. PHP and captive screens use system fonts.
  Captive sources and router distribution copies remain identical.
  Account summary controls, conditional game discovery, payment handlers and
  session behavior remain intact. No runtime credentials or customer data are
  part of this source change.

Regression protection
  tests/regression/ui_contract.js checks balanced stylesheet blocks, captive task
  headings, persistent field labels, unique control IDs and recursive router
  mirror parity without needing frontend dependencies.
  Portal browser screenshots verify navigation text at a minimum 4.5:1 contrast,
  selected/current-page state and horizontal overflow on desktop and phone.
  The review caught and corrected an account overview omission, white menu text
  on a white surface and a missing responsive-block closing brace.
